# 插画头像动效

## 目标与目录
流程：上传图 → 提取头像 → 定位眼睛 → 匹配外缘颜色 → 套用动效 → 本地验收 → 导出资源。
本 SKILL.md 所在目录就是 helper root。Windows 使用 python 或 py -3。先读 README-local.md 中的命令。
每个人物使用独立 cases/<slug>，保留 source 原图、生成图、canonical 和校准记录。已有灰发/粉发项目作为效果参考，不覆盖已有角色。

## 1. 判断与准备输入
查看用户原图；如用户提供风格参考，一并查看。已有同风格插画直接使用；多视图先确认正面区域，不能仅因横图较宽就三等分。
照片、全身照或复杂背景用当前可用的图像生成/编辑工具提取头像并适配 style-lock.md。附上身份原图与风格参考，保留头发/毛色、配饰、物种和完整轮廓。动物保留耳朵、鼻子、胡须，不套人类发型。
目标为正方形透明头像、黑色实心胶囊眼、自然倾斜。普通照片转换依赖宿主生成工具；本地 HTML 上传不执行照片生成。

## 2. 背景与眼睛坐标
matte.py 处理边缘连通白底/绿底；干净 alpha 保留。检查深浅底和棋盘底，保留浅色头发、白毛、耳环和胡须。复杂背景应回到图像编辑步骤。
先完成裁切和等比例补方，再运行 extract-eyes.py。不要把非方图直接拉成正方形。
检查两眼坐标，防止黑发、鼻子和配饰误识别。检测器会尝试更暗阈值分离深色毛发；仍需视觉复核。检测失败时，在本人物 canonical 上测量两个眼睛，用两个独立 --correct 参数纠正，记录人工校准。
禁止沿用灰发/粉发眼睛坐标或 KNOWN_GRAY_EYES。定位后若更改裁切、比例、角度，必须重新定位。
eyes.json 描述 canonical 像素坐标，pack.json 使用 0–100 归一化坐标。两者不能混用。眼睛尺寸使用胶囊短轴/长轴；tiltSource=eye-axis 时倾斜取眼睛长轴，eye-line 表示两眼连线回退。保留构建器的 eyeExtent，不用旧角色固定尺寸覆盖。

## 3. 去眼底图与外缘
build-pack.py --eyes 生成去眼 front.png 和 pack.json。播放器使用去眼底图。构建后读取 report.json 的 confidence、review、tiltSource、bakedEyeRemain 和 timingMs；ok=true 只表示构建成功，review 非空必须处理或明确说明，不能当成验收通过。
放大检查眼部，没有原黑眼、黑圈、透明洞或显眼平涂补丁；新版去眼会扩大抗锯齿清理范围并平滑修补条纹；深色毛发不能为了检查通过而漂白。
rim 从本人物外缘自动采样。若被背景/脸色污染，从外层头发或毛发选代表色写入 pack.json 的 rim，格式 #RRGGBB，并记录理由。浅灰、浅粉不是固定通用颜色。
默认薄外缘、圆润无缝接合、固定厚度、正面小角度转头；保持正面投影比例，整个头像和眼睛协调跟随鼠标。

## 4. 动效接入
本包独立运行时见 runtime/ani-bot。新人物默认使用 runtime/ani-bot/catalog.js 的 27 个状态，对齐灰发版保留列表。使用 templates/preview.html 与 templates/preview.js（复制到 cases/<slug>/） 作为本地单窗口预览模板，替换人物标题，按相对路径读取新人物资源。按钮、下拉、上一个/下一个和自动切换共用同一目录。demo/demo.js 的 8 个入口仅是旧示例，不能用它代替完整交付。旧灰发版其他修复仍需逐项验证。
表情和身体动作都要接入：player.js 通过 body-motion.js 从引擎帧的 zoom、squash 和 offset 计算位移和缩放，将底图与眼睛整体变换，与灰发版的动作适配方式一致。验收受阻、开心等动作时必须确认头部位置/尺度随时间变化，不能仅核对状态名称和眼睛。
闭眼包括圆眼眨眼必须保留黑色细线；最终屏幕尺寸下仍可见。若不满足，修复运行时并复测。
排除旋转到背面、明显缩小的展示动作。脸还在而眼睛消失的状态直接移除，并同步按钮、下拉、自动切换与公共状态调用。
不要为增加状态数量重新启用旧项目删除的动作。按当前运行时实际支持的状态交付。

## 5. 本地验收
启动 serve.py，仅绑定本机，复用匹配的服务。打开 /cases/<slug>/preview.html。
先运行 python accuracy-e2e.py 检查已知眼位、倾斜、尺寸、背景与修补误差；这是合成样例测试，不能替代真实人物验收。
逐人物保存实际截图和验收结果到 cases/<slug>/evidence：
- 左右上下跟随；极限位置没有残留原眼、黑洞或双眼，头部转动和眼睛运动协调。
- 实时播放完整待机循环，捕获真正眨眼的闭合帧，检查睡眠与唤醒；圆眼闭合是一条黑线。
- 每个开放状态从待机进入，覆盖完整片段、随机变体和相邻状态切换。
- 正常大小、约 100px 与约 50px 头像大小下检查两只眼睛。截图及像素检查与状态数据结合；不以 lid 数值或非空纹理作为可见性证明。
- 暂停/恢复、减少动态效果、dispose 和控制台错误。
- Python serve.py 的真实 multipart 上传：适配插画可构建，普通照片按约定返回 needs-stylization。
inspect-eyeless.py 只检查底图清理，不能替代动效验收；空 cases 不是通过。深色动物眼周需人工视觉复核。
失败就修复重测或移除该状态。历史样例与截图不代表新人物通过，区分实际测试、人工修正和未验证部分。

## 6. 交付
交付本人物 canonical、front.png、pack.json、eyes.json、来源/许可、校准记录及验收截图。
用 export-pack.py 输出仅含当前人物的 ZIP、本地服务和运行时。不要混入其他私有人物素材。
提供可访问预览地址、人物目录和 ZIP。新人物默认通过 serve.py 预览；本包不包含历史人物素材。
不要宣称任意图片都能无误自动转换，也不要声称已经接入用户桌面应用。

## Ani 2.0 同步说明
本版同步上传构建精度修复、素材缓存、按显示尺寸渲染与锁定姿态处理。公开包保留 27 状态目录和独立预览，图片、应用内部路径及历史人物不随包发布。
深色脸部可在未显式提供 eyePaint 时自动选择白眼；构建器默认仍写黑色，修改前先核对用户视觉要求。
