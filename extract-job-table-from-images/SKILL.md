# Extract Job Table From Images

把用户提供的招聘图片整理为结构清晰、可核对的三列表格。严格依据图片与用户要求，不补写没有证据的信息。

## 处理流程

1. 收集本轮用户提供的全部图片和文字要求。
2. 逐张放大检查图片；按自然阅读顺序识别所有岗位记录。图片模糊时，先尽力读取可见部分，不把猜测当成事实。
3. 为每条记录提取：
   - `岗位`：职位名称，保留级别、方向、职能等有辨识度的信息。
   - `公司`：招聘主体或图片明确标示的公司名称。
   - `地点`：城市、区域或明确标示的远程/混合办公信息。
4. 完成全部图片的初步提取后，再统一应用用户的筛选要求，例如指定岗位、公司、城市、关键词、排除项、排序或去重规则。
5. 复核每行是否能追溯到图片中的可见信息，并检查漏行、错列和跨图片重复。
6. 输出最终表格；用户未指定文件格式时，直接输出 Markdown 表格。用户明确要求 Excel、CSV 或其他文件时，再创建相应文件。

## 字段与规范

- 表头和顺序固定为：`岗位 | 公司 | 地点`。
- 每个岗位单独占一行。同一公司有多个岗位时不要合并岗位名称。
- 只做不改变含义的清理，例如去除多余空格、重复标点和换行。
- 删除岗位名称中仅表示招聘人数或 HC 数量的标记，例如 `*1-2`、`1-2人`、`招2人`、`HC 2`；保留岗位本身及级别、方向、Base、出差等实质信息。
- 同一条招聘记录在多张图片中重复出现时，按“岗位 + 公司 + 地点”去重。
- 用户给出的筛选规则优先于默认规则；筛选条件不明确但可按常见含义安全执行时，采用最保守的解释。
- 图片中未注明某字段时填写 `未注明`。
- 字段存在多种合理读法、文字被遮挡或清晰度不足时填写 `待确认`，不要臆测。
- 不根据公司常识、职位名称或网络信息推断地点、公司或岗位。
- 不主动上网补齐缺失字段；只有用户明确要求核实时才搜索。
- 不从姓名、头像或外观推断敏感属性。

## 多图片与版式判断

- 先识别标题、栏目名、卡片边界、表格行列和上下文，再决定字段归属。
- 图片包含多个公司或多个城市分区时，持续继承最近且明确适用的标题，直到出现新的分区标题。
- 一张图片是上一张的续页时，结合相邻图片判断，但只继承版式上下文，不继承未经显示的字段值。
- 同一岗位明确列出多个地点时：
  - 若图片把地点作为并列适用范围，保留在同一单元格，用 `、` 分隔。
  - 若每个地点代表独立招聘记录，拆成多行。

## 输出格式

默认只交付简洁结果：

| 岗位 | 公司 | 地点 |
|---|---|---|
| 示例岗位 | 示例公司 | 示例地点 |

- 若筛选后无匹配项，仍输出表头，并说明“未找到符合要求的岗位”。
- 若存在 `待确认` 项，在表格后用一句话指出对应行和需确认字段。
- 不额外添加序号、来源、备注等列，除非用户明确要求。
- 用户继续补发图片时，把新结果并入本轮已有结果，重新筛选、去重并输出完整表格。
